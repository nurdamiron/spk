# Строй-Трекер: план разработки

Веб-приложение для ежедневного учёта на объектах: **выполнение против расходов** по позициям КП.
Цель: в любой момент видеть по каждому объекту, сколько освоено, сколько потрачено, какая прибыль сейчас и какой будет в конце.

- Пользователи: владелец, прораб/бригадир, кассир/бухгалтер.
- Масштаб: 5–10 объектов одновременно, ввод каждый день, с телефона, часто со слабым интернетом.
- Оплата бригадам: за час, за день, за объём, фикс за этап (на одном объекте могут быть все четыре).

---

## 1. Основные понятия

| Термин | Что значит |
|---|---|
| **Позиция КП** | Строка КП/ВОР: наименование, ед., объём, цена заказчику за ед., плановая себестоимость за ед. |
| **Выполнение** | Сколько единиц позиции сделано за день (с фото). |
| **Освоено** | Выполнение в деньгах по цене КП: `объём × цена заказчику`. Это то, что ты «заработал» на бумаге. |
| **Плановая с/с освоенного** | Сколько должны были потратить на сделанный объём: `объём × плановая с/с за ед.` |
| **Фактическая с/с** | Сколько реально потратили: труд + материалы + техника + прочее (+ доля общих расходов). |
| **Начислено** | Сколько бригада заработала по своей ставке. |
| **Выдано** | Сколько денег бригаде фактически дали (авансы, расчёты). |
| **Базовый план (baseline)** | Зафиксированная версия КП на момент договора. Изменения идут только через допсоглашение (новая версия). |

---

## 2. Как фиксируем стоимость каждой позиции

### 2.1. Цена заказчику
Берётся из КП/договора, без НДС. После подписания договора позиция **блокируется**: поменять цену можно только через допсоглашение (новая версия КП, старая остаётся в истории).

### 2.2. Плановая себестоимость
У каждой позиции плановая с/с за единицу, **разбитая по статьям** (разбивка необязательна, но желательна):

| Статья | Пример: канализация Ø160, за 1 м |
|---|---|
| Материалы | 9 000 |
| Труд | 6 000 |
| Техника | 3 500 |
| Прочее | 500 |
| **Итого план с/с** | **19 000** |
| Цена заказчику | 27 000 |
| Плановая маржа | 8 000 (29,6%) |

Как заполнять:
1. **Из файла.** Если в ВОР есть колонки с/с, импорт их подхватывает.
2. **Быстрый способ.** % от цены на раздел или весь объект («с/с = 70%»), разбивку по статьям можно добавить потом.
3. **Из ставок бригад.** Если у бригады сдельная расценка на позицию, статья «Труд» подставляется из неё автоматически.

Разбивка нужна, чтобы видеть, **где именно** перерасход: на материале, на людях или на технике.

### 2.3. Версии
- `v1`: базовый план при подписании.
- `v2+`: допсоглашения, доп. работы.
- Дашборд считает по последней утверждённой версии, но показывает отклонение от `v1`.

## 3. Как удобно заносим (ввод данных)

### 3.1. Ежедневный отчёт прораба (главный экран)
Один отчёт = объект + дата. Три блока:

**А. Выполнение**
- «+ позиция»: поиск по названию из КП текущего объекта, недавние позиции наверху.
- Ввод объёма в единицах КП, цифровая клавиатура. Сразу видно «сделано 70 из 100 м».
- Фото (1–5 шт.), сжимаются на телефоне до ~300 КБ.
- Объём больше остатка → предупреждение и вопрос «Это доп. работа?» → уходит владельцу на согласование.
- Работы нет в КП → «Доп. работа» (свободный текст + ед. + объём) → на согласование.

**Б. Люди и техника**
- Список **предзаполнен составом вчерашнего дня**, прораб только правит.
- По каждой строке в зависимости от типа ставки:
  - за час → часы;
  - за день → отметка «был» (или 0,5 дня);
  - за объём → ничего не вводится, считается из блока А (бригада ↔ позиция);
  - фикс за этап → ничего, считается из % готовности этапа.
- Необязательно: «на какой позиции работали» (для точного разнесения труда). Если пусто, распределяется автоматически (см. 4.4).

**В. Расходы**
- Сумма, категория (материал / техника / топливо / доставка / прочее), позиция КП (необязательно), фото чека, комментарий.
- **Источник денег:** «из подотчёта» (по умолчанию для прораба) / оплатил офис / перечисление.
- **НДС:** «есть ЭСФ с НДС» или «без НДС / без ЭСФ» (см. 4.8).
- Для материала: кол-во и ед. («Труба ПЭ 110, 40 м»). Это нужно для сравнения «закуплено против уложено».

**Кнопка «Отправить».** Без интернета отчёт сохраняется в телефоне и уходит сам, когда связь появится.

### 3.2. Правила ввода
- Отчёт за прошлые даты можно отправить, он получит пометку «задним числом».
- Отправленный отчёт прораб может править 24 часа, потом только владелец. Каждая правка в журнале изменений (кто, когда, было → стало).
- Цель по времени: весь отчёт за **≤ 2 минуты**.

### 3.3. Ввод у владельца и кассира
- **Выдача денег бригаде:** кому, сумма, аванс или расчёт, объект (необязательно).
- **Выдача в подотчёт прорабу:** кому, сумма, объект, комментарий («на трубу и доставку»).
- **Общие расходы:** аренда бытовки, бензин, связь, по объекту или по компании.
- **Оплата от заказчика:** сумма, дата, по какому акту.
- **Импорт КП** из Excel: загрузил файл → сопоставил колонки (автоопределение) → превью → подтвердить.

## 4. Как всё рассчитывается

Обозначения по позиции `i`:
`Q_i` — объём по КП, `q_i` — выполнено нарастающим, `P_i` — цена заказчику за ед., `C_i` — план с/с за ед.

### 4.1. По позиции
```
Готовность_i           = q_i / Q_i
Освоено_i              = q_i × P_i
План_сс_освоенного_i   = q_i × C_i
Факт_сс_i              = Труд_i + Материал_i + Техника_i + Прочее_i + Доля_общих_i
Прибыль_i              = Освоено_i − Факт_сс_i
Маржа_i                = Прибыль_i / Освоено_i
Отклонение_i           = План_сс_освоенного_i − Факт_сс_i   (минус = перерасход)
Индекс_затрат_i (CPI)  = План_сс_освоенного_i / Факт_сс_i   (<1 = тратим больше плана)
```

### 4.2. По объекту
```
Освоено          = Σ Освоено_i
Факт_сс          = Σ Факт_сс_i  (включая общие расходы объекта)
Прибыль сейчас   = Освоено − Факт_сс
Готовность       = Освоено / Сумма договора
```

### 4.3. Начисление труда (по типу ставки)
| Тип | Формула начисления за день |
|---|---|
| За час | `часы × ставка` |
| За день | `дни × ставка` |
| За объём | `выполнено_за_день(позиция) × расценка(бригада, позиция)` |
| Фикс за этап | `Сумма_фикса × (Готовность_этапа_сегодня − Готовность_этапа_вчера)` |

`Готовность_этапа = Σ Освоено_i / Σ (Q_i × P_i)` по позициям этапа, то есть взвешенно по деньгам, а не по метрам.

Долг бригаде: `Начислено − Выдано` (плюс = мы должны, минус = переплата/аванс).

### 4.4. Разнесение расходов, не привязанных к позиции
Порядок:
1. Указана позиция → на неё напрямую.
2. Сдельщик → на позицию, по которой считается расценка.
3. Почасовые/подённые без позиции → **пропорционально освоению за тот же день** по позициям, где в этот день было выполнение.
4. Общие расходы объекта (бытовка, топливо, доставка) → **пропорционально освоению нарастающим итогом** по всем позициям объекта.
5. Общие расходы компании (офис, твоя машина) → на объекты пропорционально освоению за месяц (этап 3, по желанию).

Распределение пересчитывается автоматически при каждом новом отчёте, в базе хранятся только исходные данные.

### 4.5. Материалы: «закуплено против уложено»
В MVP материал списывается в с/с в момент покупки. Из-за этого бывает «временный минус»: трубу купили, а ещё не уложили. Чтобы это не пугало:
```
Материал_закуплено_i      = Σ расходов-материалов по позиции
Материал_норма_на_факт_i  = q_i × План_материал_за_ед_i
Материал_в_запасе_i       ≈ Материал_закуплено_i − Материал_норма_на_факт_i
```
Дашборд показывает «≈ 1,2 млн в материале на объекте» и считает **скорректированную прибыль** = прибыль + материал в запасе.
Этап 2: полноценный склад объекта (приход / списание по норме / перемещение между объектами).

### 4.6. Прогноз на завершение
По каждой позиции:
```
Ф_ед_i = Факт_сс_i / q_i                  (если готовность ≥ 10%, иначе берём C_i)
Прогноз_сс_i = Факт_сс_i + (Q_i − q_i) × Ф_ед_i
```
По объекту:
```
Прогноз_сс       = Σ Прогноз_сс_i + прогноз общих (средн. в день × оставшиеся дни)
Прогноз_прибыли  = Сумма договора − Прогноз_сс
Темп             = выполнено за последние 7 дней (в ₸ освоения) / 7
Прогноз_даты     = сегодня + (Сумма договора − Освоено) / Темп
```

### 4.7а. Подотчёт прораба
Простая схема (MVP): выдал → прораб тратит через отчёт → видно остаток.
```
Остаток_подотчёта = Σ выдано в подотчёт − Σ расходов «из подотчёта» − Σ возвратов
```
- Прораб видит свой остаток прямо в отчёте («на руках: 120 000 ₸»).
- Каждый расход из подотчёта с фото чека и комментарием. Без чека расход помечается «без подтверждения».
- Владелец видит по каждому прорабу: выдано, отчитался, остаток, сколько без чеков.
- Остаток не тратится сам: возврат или перенос на другой объект вносится отдельной операцией.

### 4.7. Деньги (cash-flow, этап 2)
```
Актировано        = Σ освоено, вошедшее в акты
Дебиторка         = Актировано − Оплачено заказчиком
Деньги в объекте  = Выдано бригадам + Оплачено расходов − Получено от заказчика
```

### 4.8. НДС (компания — плательщик НДС)
Ставка задаётся в настройках компании (по умолчанию 16%, действует в РК с 2026 года).

**Доход:** цены КП хранятся без НДС, освоено и прибыль считаются без НДС. Сумма договора и акты показываются в двух видах: без НДС и с НДС.

**Расходы:** при вводе у расхода выбирается вариант:
| Вариант | Что в с/с | НДС к зачёту |
|---|---|---|
| С НДС, есть ЭСФ (поставщик — плательщик НДС) | сумма без НДС | выделенный НДС |
| Без ЭСФ / нал / поставщик не плательщик НДС | **вся сумма** | 0 |
| Зарплата, подённые бригады | вся сумма | 0 |

Поэтому покупка за наличку без ЭСФ реально дороже на 16% и в отчётах это видно. Дашборд покажет «потеряно на НДС без ЭСФ» по объекту.

**НДС к уплате (этап 3, справочно):**
```
НДС начисленный  = Актировано × ставка
НДС к зачёту     = Σ НДС по расходам с ЭСФ
НДС к уплате     ≈ НДС начисленный − НДС к зачёту
```
Это управленческая оценка для понимания денег, не налоговый учёт.

## 5. Сигналы (уведомления)
| Сигнал | Условие |
|---|---|
| Позиция в минусе | `Маржа_i < 0` при готовности ≥ 10% |
| Перерасход | `CPI_i < 0,9` |
| Маржа объекта падает | прогнозная маржа ниже плановой больше чем на 5 п.п. |
| Деньги без работы | 2+ дня подряд есть расходы, нет выполнения |
| Отчёт не сдан | к 21:00 нет отчёта по активному объекту |
| Переплата бригаде | `Выдано − Начислено > порог` |
| Превышение КП | `q_i > Q_i` без согласованной доп. работы |

Каналы: внутри сайта (колокольчик), Telegram-бот владельцу (этап 2).

## 6. Модель данных (Postgres)

Деньги хранятся в `bigint` (тенге, без копеек), объёмы в `numeric(14,3)`. У всех таблиц `id uuid`, `company_id`, `created_at`, `created_by`.

```
companies           (name, vat_rule, settings)
users               (phone, name, role: owner|foreman|cashier)
object_members      (object_id, user_id, role)

objects             (name, customer, contract_no, contract_sum, start_date, end_date, status)
kp_versions         (object_id, version_no, kind: base|addendum, approved_at, approved_by)
kp_sections         (kp_version_id, name, sort)
kp_items            (kp_version_id, section_id, code, name, unit, qty,
                     price_customer, cost_material, cost_labor, cost_equipment, cost_other,
                     sort)
stages              (object_id, name)                     -- для фикса за этап
stage_items         (stage_id, kp_item_id)

crews               (name, leader_phone, kind: crew|person|equipment)
crew_rates          (crew_id, object_id?, rate_type: hour|day|volume|fixed,
                     rate, kp_item_id?, stage_id?, valid_from)

daily_reports       (object_id, report_date, author_id, submitted_at, is_backdated, status)
progress_entries    (report_id, kp_item_id | extra_work_id, qty, note)
labor_entries       (report_id, crew_id, hours, days, kp_item_id?)
expenses            (object_id, report_id?, date, category, amount_gross,
                     vat_mode: esf_vat|no_vat, vat_amount, amount_cost,   -- amount_cost идёт в с/с
                     kp_item_id?, material_name?, material_qty?, material_unit?,
                     funding: imprest|office|transfer, imprest_holder_id?,
                     has_receipt, comment, scope: object|company)
imprest_moves       (holder_id, object_id?, date, amount,
                     kind: issue|return|transfer, comment)              -- подотчёт
photos              (owner_type, owner_id, storage_path)

extra_works         (object_id, name, unit, qty, price_customer?, status: pending|approved|rejected)
payouts             (crew_id, object_id?, date, amount, kind: advance|settlement, note)
customer_payments   (object_id, date, amount, act_id?)
acts                (object_id, period_from, period_to, number, status)       -- этап 2
audit_log           (table, row_id, user_id, before, after, at)
```

**Расчёты = SQL-представления (views)**, а не хранимые суммы:
`v_item_progress`, `v_labor_accruals`, `v_cost_allocation`, `v_item_financials`, `v_object_financials`, `v_crew_balance`, `v_forecast`.
Исходные данные — единственный источник правды: исправил отчёт, и все цифры пересчитались сами.

Доступ (RLS):
- **Владелец** — единственный, кто видит цены КП, плановую с/с, прибыль, маржу и прогноз.
- **Прораб** видит только свои объекты: позиции (наименование, ед., объём, сделано), свои отчёты, свой подотчёт. Цен и прибыли не видит. Для него отдельные views без денежных колонок.
- **Кассир** видит выдачи, подотчёт, расходы. Прибыль не видит.
- **Партнёры** в первой версии доступа не получают. Если понадобится, добавим роль «наблюдатель» с выбором, что показывать.

## 7. Технологии

| Слой | Выбор | Почему |
|---|---|---|
| Фронт + бэк | **Next.js (App Router) + TypeScript** | один проект, быстрые экраны, хорошо работает на телефоне |
| UI | Tailwind + shadcn/ui | быстро и аккуратно |
| База, логины, фото | **Supabase** (Postgres, Auth по SMS/OTP, Storage, RLS) | всё в одном, права на уровне базы |
| Офлайн | PWA + очередь в IndexedDB | слабый интернет на объектах |
| Импорт Excel | SheetJS | ВОР/КП уже в xlsx |
| Графики | Recharts | освоено против потрачено |
| Уведомления | Telegram Bot API (этап 2) | все уже в Telegram |
| Хостинг | Vercel + Supabase cloud | без своих серверов |
| Языки | ru + kz (i18n) | для прорабов |

## 8. Зависимости модулей (что от чего зависит)

```
Auth/роли
  └─ Объекты + участники
       ├─ Импорт КП → kp_versions / kp_items ─┬─ Этапы (для фикса)
       │                                       │
       ├─ Бригады + ставки ────────────────────┤
       │                                       ▼
       └─────────────────────────────► Ежедневный отчёт (выполнение / люди / расходы / фото)
                                                │
                                                ▼
                               Расчётные views (освоено, начисления, разнесение, с/с)
                                    │            │              │
                                    ▼            ▼              ▼
                           Дашборд объекта   Баланс бригад   Сводка по объектам
                                    │
                                    ▼
                    Сигналы → Telegram │ Прогноз │ Акты и деньги заказчика │ Склад
```

Критический путь: **Auth → Объекты → Импорт КП → Бригады → Отчёт → Views → Дашборд.** Всё остальное надстройки.

## 9. План по этапам

### Этап 0. Кликабельный прототип (3–4 дня)
- Экраны с фейковыми данными Коктобе 138: отчёт прораба (телефон), дашборд объекта, все объекты, бригады.
- Показать прорабу, собрать замечания по вводу.
- **Готово, когда:** прораб заполняет фейковый отчёт за ≤ 2 мин без подсказок.

### Этап 1. MVP (3–4 недели)
| Неделя | Задачи |
|---|---|
| 1 | Проект Next.js + Supabase, схема БД, миграции, RLS, вход по телефону, роли, объекты |
| 2 | Импорт КП из Excel (сопоставление колонок, превью), редактор позиций и плановой с/с, бригады и ставки |
| 3 | Ежедневный отчёт (3 блока, фото, предзаполнение, офлайн-очередь, НДС/ЭСФ у расхода), выдачи бригадам, подотчёт прораба |
| 4 | Views расчётов, дашборд объекта, сводка по объектам, баланс бригад, тесты формул на данных Коктобе |

**Готово, когда:** 1 реальный объект неделю ведётся в системе, а цифры сходятся с ручным подсчётом в Excel.

### Этап 2. Контроль (2–3 недели)
- Сигналы + Telegram-бот владельцу.
- Прогноз на завершение, темп, прогноз даты.
- Доп. работы и допсоглашения (версии КП).
- Склад объекта: закуплено / уложено / перемещение.
- Журнал изменений в интерфейсе.

### Этап 3. Деньги и документы (2–3 недели)
- Акты выполненных работ за период → Excel/PDF.
- Оплаты заказчика, дебиторка, cash-flow по объекту.
- Общие расходы компании с распределением.
- Экспорт всего в Excel.

### Этап 4. Развитие
- Ввод через Telegram (текст или голос → ИИ разбирает в отчёт, прораб подтверждает).
- Своя база фактических себестоимостей → подстановка в новые КП (связка с `price-base`).
- Сравнение бригад по производительности и стоимости за единицу.

## 10. Тестирование расчётов
- Набор эталонных сценариев (юнит-тесты на SQL views):
  1. сдельщик + подённый на одной позиции;
  2. фикс за этап при 40% готовности;
  3. общий расход 300 000 на 3 позиции с разным освоением;
  4. материал закуплен, не уложен;
  5. отчёт задним числом и правка отчёта.
- Сверка с ручным Excel на реальных данных объекта в течение первой недели.

## 11. Решения и открытые вопросы

**Решено (16.11.2026):**
1. Компания работает **с НДС** → расходы делятся на «с ЭСФ» и «без ЭСФ» (раздел 4.8).
2. Прибыль, цены и маржу видит **только владелец**. Партнёры пока без доступа.
3. **Подотчёт прораба нужен**, в простом виде: выдача → расходы с чеком и комментарием → остаток (раздел 4.7а).

**Открыто (пока берём значение по умолчанию, поменять можно в настройках):**
4. Фикс за этап → по умолчанию начисляем по % готовности, выплату ведём отдельно.
5. Казахский язык → в MVP только русский, но тексты сразу выносим в i18n, чтобы добавить казахский без переделки.
6. Название приложения → рабочее «Строй-Трекер».
