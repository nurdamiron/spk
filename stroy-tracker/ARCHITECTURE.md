# Строй Трекер v2: техническая архитектура

Статус: черновик на согласование. Код и база не менялись.
Принцип: **одна база, три входа** (сайт, WhatsApp, Google Sheets), чат не хранит данные.

## 1. Схема

```
 Прораб / бригадир            Владелец / бухгалтер
 ┌────────────┐  ┌────────┐  ┌────────────┐  ┌───────────────┐
 │ WhatsApp   │  │ Сайт   │  │ Сайт (ПК)  │  │ Google Sheets │
 └─────┬──────┘  └───┬────┘  └─────┬──────┘  └───────┬───────┘
       │ webhook     │ форма       │                 │ зеркало / прайс
       ▼             ▼             ▼                 ▼
 ┌──────────────────────────────────────────────────────────┐
 │ Next.js на Vercel: единый слой приёма и расчётов (/api)   │
 │  ingest → parse → validate → save  ·  calc  ·  sync       │
 └──────┬───────────────┬──────────────────┬────────────────┘
        │               │                  │
        ▼               ▼                  ▼
   Supabase Postgres  Supabase Storage   Очередь и cron
   (источник правды)  (фото, договоры)   (напоминания, синк)
```

Все клиенты ходят только через серверный слой. Прямого доступа к базе из браузера нет (RLS без политик, как сейчас).

## 2. Компоненты

| Компонент | Что делает | Технология |
|---|---|---|
| Сайт | Формы, свод, документы, прайс, табель | Текущий Next.js 16 + PWA, не переписываем |
| Приём (`/api/ingest`) | Единая точка записи для сайта и бота: проверка прав, дедуп по `client_id`, расчёт сумм на сервере | Расширение текущего `/api/reports` |
| WhatsApp-шлюз | Получает сообщения и файлы, отвечает «Записал… Верно?» | Подключение по QR (выбор владельца). Отдельный сервис на сервере с постоянным процессом, не на Vercel |
| Разбор сообщений | Текст или голос → поля отчёта: расход, люди, техника, сделано / не сделано | Claude API (структурированный вывод), голос через распознавание речи |
| Очередь разбора | Что бот не понял, попадает на экран «Разобрать вручную» | Таблица `inbox` |
| Sheets-синк | База → Sheets (зеркало, только чтение), прайс Sheets ↔ база | Google Sheets API, cron раз в 5 минут и по событию |
| Напоминания | Вечером «отчитайтесь», утром «кто не отчитался» | Vercel Cron + WhatsApp-шлюз |

## 3. Модель данных: что добавляем (миграция 006)

Существующие таблицы (`objects`, `kp_items`, `crews`, `reports`, `expenses`, `progress_entries`, `labor_entries`, `payouts`, `imprest_moves`, `price_*`) не меняем. Только добавляем:

| Таблица | Поля | Зачем |
|---|---|---|
| `documents` | object_id, kind (contract, invoice, act, other), number, counterparty, amount, due_date, status (waiting, paid, overdue), file_path, created_by | Договоры и счета |
| `equipment` | id, name, kind, rate_type (hour, day, fixed), rate | Справочник техники |
| `equipment_entries` | report_id, equipment_id, qty, amount | Техника по дням |
| `headcount_entries` | report_id, role_or_crew, people, hours | Люди по дням |
| `report_notes` | report_id, done text, not_done text, reason text | Вечернее «сделано / не сделано» |
| `inbox` | id, source (whatsapp, site), raw_text, files, parsed jsonb, status (new, parsed, needs_review, saved, rejected), object_id, sender | Всё, что пришло извне, до записи |
| `audit_log` | table, row_id, field, old, new, who, when, source | История правок (кто, когда, откуда) |
| `wa_links` | phone, profile_id, object_id | Какой номер за каким прорабом и проектом |
| `sheet_sync` | table, last_synced_at, last_error | Состояние синхронизации |

Правило денег то же: тенге, целые числа, суммы считает сервер.

## 4. Потоки данных

**Отчёт из WhatsApp**
1. Сообщение приходит в шлюз → запись в `inbox` (`new`).
2. Номер сверяется с `wa_links`. Чужой номер игнорируется.
3. Claude разбирает текст в JSON. Уверенный разбор получает статус `parsed`, неуверенный `needs_review`.
4. Бот отвечает прорабу сводкой «Записал: … Верно?». «Да» вызывает `/api/ingest`, запись попадает в базу с `source=whatsapp`. «Нет» открывает правку.
5. Сайт сразу видит запись, Sheets получает её при ближайшем синке.

**Отчёт с сайта** идёт тем же `/api/ingest` с `source=site`, без разбора.

**Прайс.** Лист «Прайс» в Sheets, при изменении синк пишет в `price_*` и в `audit_log`. На проекте цену можно переопределить, с пометкой кто и когда.

**Напоминания.** Cron в 18:00 проверяет, у кого по активным объектам нет отчёта за сегодня, и шлёт напоминание. В 09:00 владельцу уходит список «не отчитались вчера».

## 5. Google Sheets

| Лист | Направление |
|---|---|
| Расходы, Отчёты, Табель, Техника, Документы | база → Sheets, только чтение |
| Прайс | Sheets ↔ база |
| Свод по объектам | база → Sheets, формулы в самой таблице |

Правки по расходам и отчётам делаются на сайте или через бота, чтобы работала история. Лист-зеркало защищён от записи.

## 6. Права

Роли остаются: `owner`, `foreman`, `cashier`. Прораб видит и пишет только в свои объекты (`object_members`). Бухгалтер видит деньги и документы. Владелец видит всё. Для WhatsApp роль берётся из `wa_links`.

## 7. Дизайн

Берём существующую систему как есть, новые экраны делаем из тех же токенов:

- Тёмная тема, токены `--bg`, `--card`, `--tx`, `--ac`, `--ok`, `--warn`, `--bad` в `globals.css`, радиус `--r: 22px`.
- Мобильный приоритет: кнопки не меньше 44 px, шрифт полей не меньше 16 px, нижнее меню, главная кнопка у нижнего края, safe-area.
- Таблицы на телефоне превращаются в карточки, поиск на весь экран (см. `MOBILE.md`).
- Меню из 3 пунктов плюс «Ещё», как после упрощения.
- Новые экраны: **Входящие** (разбор вручную), **Документы**, **Техника и люди**, **Кто не отчитался**.
- Статусы везде одним цветом: зелёный ok, жёлтый ждёт, красный просрочено или не понято.

## 8. Этапы

| # | Этап | Результат |
|---|---|---|
| 1 | Миграция 006 + `/api/ingest` + аудит | База готова, сайт пишет через новый слой |
| 2 | Экраны: документы, техника и люди, вечерний отчёт, кто не отчитался | Всё можно вести с сайта |
| 3 | Sheets: зеркало и прайс | Таблица живёт параллельно |
| 4 | Разбор текста и голоса, экран «Входящие» | Проверка разбора на тестовых фразах без WhatsApp |
| 5 | WhatsApp-шлюз по QR, `wa_links`, напоминания | Прорабы пишут в чат |
| 6 | Переключение основного домена | Старая версия остаётся в git и в старом деплое |

Работа идёт в отдельной ветке и на превью-адресе. `main` и `stroy-tracker.vercel.app` не меняются до твоего «ок».

## 9. Риски

- Подключение WhatsApp по QR неофициальное: номер могут ограничить, сессия может слетать. Нужны резервный канал (сайт) и мониторинг сессии. Официальный API на отдельном номере безопаснее.
- Разбор свободного текста ошибается на суммах. Поэтому бот всегда подтверждает запись, а неуверенное уходит в «Входящие».
- Двусторонний синк возможен только для прайса. Остальное зеркало.
- Шлюз WhatsApp требует постоянного процесса, на Vercel он не живёт. Нужен небольшой сервер.
